# Performance results — 2026-10-14 (Haswell i3-4130, 1 thread)

Machine: Intel Core i3-4130 @ 3.40 GHz (2C/4T, Haswell), 3 MB L3, Win10 x64.
Compiler: Tessera C backend -> **clang 23.1.3** (`-O2 -fwrapv -std=c11`). AC power, turbo N/A (fixed
3.4 GHz), concurrency 1. (Repro protocol to be tightened: governor pinning + repeated runs/median.)

## Nodes per second (raw search speed, as reported by each engine's own bench)
| Engine | Search | Nodes | Time | **nps** |
|---|---|---|---|---|
| Tessera (this project, Oct 14) | 10x10 mailbox copy-make, alpha-beta + quiescence + MVV-LVA + TT(zobrist), material eval | 2,031,730 (`bench 5`, 6-position FEN set) | 16,214 ms | **125,307** |
| Stockfish 19 (universal -> AVX2/BMI2 on this CPU) | full (NNUE) | 2,497,913 (`bench`) | 5,326 ms | **469,003** |

**Gap: Tessera ~= 27% of Stockfish nps (~3.7x).**

## Honest caveats
- nps across *different* search algorithms is not a strength measure. The C++ **reference engine
  (same algorithm as Tessera)** — to isolate *language/compiler* speed from *algorithm* speed — is
  still pending; expectation (stated up front): near parity, since both lower to clang `-O2` C.
- Tessera is a first cut: material-only eval, 10x10 copy-make gen (per-node zobrist recompute),
  no bitboards/magic; Stockfish is a mature NNUE engine. The realistic near-term levers are
  **bitboards/magic (speed)** and **NNUE (strength)**, plus SPRT to measure strength honestly.
- These are single bench runs; reruns/median still required before any head-to-head claim.
