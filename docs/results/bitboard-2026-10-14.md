# Bitboard movegen (E2) — 2026-10-14

Replaced the 10x10 mailbox generator with **bitboards** (`engine/bb.ter`): fancy-style
relevant-occupancy masks (each ray keeps its squares, excludes only the terminal edge square),
occupancy index via the `btable_index` builtin — **hardware `pext` under `-mbmi2` (Tier C)**, a
correct masked-bit **gather** on Tier A/B. Copy-make make/unmake. Knight/king/pawn tables built
at init; rook/bishop tables by subset enumeration.

**Perft (measured, engine/e1's exact reference numbers):**

| FEN | depth | Tessera (A/B/C) | reference |
|---|---|---|---|
| startpos | 4 | 197281 | 197281 exact |
| Kiwipete  | 3 | 97862  | 97862 exact |
| position 3| 4 | 43238  | 43238 exact |

Identical on Tier A/B/C -> pext and gather indexing agree; movegen is correct incl. castling,
en-passant, promotions.

**Movegen speed (nodes/sec, perft of the 3 positions = 338381 nodes, single thread):**
- Tier C (AVX2+BMI2, pext): **~17.8M nps**
- Tier A (SSE2) / Tier B (POPCNT), masked-bit gather: **~10.0M nps**
(pext ~1.8x the portable gather on this Haswell.)

## Honest notes
- These are **perft node counts**, not search nodes — not directly comparable to the earlier
  125 k *search* nps or Stockfish's 469 k search nps. But movegen is the per-node bottleneck, and
  raw movegen is now ~10-18M nps.
- Movegen is done; the search/UCI engine still uses the 10x10 generator. Integrating bitboards into
  the alpha-beta+TT search (with bitboard-native make/unmake and eval) is the next step, after which
  we re-measure *search* nps per tier and re-run the Stockfish match.
- Debugging trail (honest): first attempts used `(occ & mask) >> shift` indexing, which is
  **mathematically invalid** without a magic multiply, and a mask rule that excluded whole
  perimeter rays (a1 rook slid through a2). Fixed to gather/pext + terminal-only mask exclusion.
