# Self-play data run #2 — 1500 games, and what 4× the data bought

**Date:** 2026-10-14 · **Engine:** Tessera (bitboards, HCE) vs itself, node-limited 30k vs 22k
**Harness:** fastchess, `-pgnout`, opening book `engine/book.epd`, concurrency 2
**Wall time:** 39m17s for 1500 games on the i3-4130

## Data

```
games parsed      : 1500
games used        : 1500 (none skipped: no time forfeits, node limits removed the cause)
positions written : 141,656
  wins (stm)      : 39,113
  draws           : 63,904
  losses (stm)    : 38,639
  bytes           : 5,666,240
```

Game quality looks healthy: median 101 plies, 43% draws, and white wins more than black
(234 vs 180 in the first 710 games) which is the expected first-move edge.

Throughput: **~3,600 positions/minute** at concurrency 2. So 10^6 positions is about 4.6 hours and
10^7 about 46 hours on this machine — that is the wall-clock price of a serious NNUE run here.

## Training (game-level split, 32 hidden units, 60 epochs, ~4 min)

```
split by game : 1350 train games / 150 val games
val MSE       : 105,000 -> 58,775     (predicting 0 costs ~112,000)
val correlation: +0.502               (score vs actual result)
weights       : w1 [-2, 2]   psqt [-10, 9]   w2 [-9, 8]
calibration   : factor 0.883 -> scale 57
```

This run is the first with an honest validation number: the split is **by game**, not by position.
The earlier +0.600 (37k positions) and +0.890 (4k positions) were measured with a random position
split, which leaks because positions in one game share openings and tactics. The true trend is
+0.89 (leaky, 4k) -> +0.60 (leaky, 37k) -> **+0.50 (honest, 142k)**.

## What the net learned

| position | 4k net | 142k net | "sane" |
|---|---|---|---|
| white queen up, white to move | +141 | **+167** | ~+900 |
| black queen up, black to move | +141 | **+171** | ~+900 |
| white rook up, white to move | −1 | **+159** | ~+500 |
| start position | — | +97 | ~+10 |

The rook is the interesting one: it went from "worth nothing" to +159 cp, and the queen/rook
ordering is right and colour-symmetric. But every unit is still badly under-scaled — the net is
learning material through 768 sparse features with no king-safety or pawn-structure signal, on
data where 45% of labels are draws.

## Strength: still losing, but the trend is real

```
fastchess, 5+0.05, 1 thread, 16 MB
Tessera+NNUE vs Tessera+HCE
  37k positions  ->  0 wins, 1 draw, 7 losses   ( 6.25%)
  142k positions ->  2 wins, 0 draws, 10 losses (16.67%)
```

4× the data roughly tripled the score. That is the expected shape of a learning curve with no
plateau in sight yet, which says the bottleneck is data volume, not the architecture or the
pipeline.

## What this run does *not* prove

- 12 games is a smoke test, not an SPRT; 16.67% has enormous error bars.
- The comparison is against our own hand-crafted eval, not against Stockfish. The HCE engine
  itself beats `Stockfish 19 Skill Level 0` 6-2, so "NNUE vs HCE" is the right developmental
  question but not a strength claim in absolute terms.
- One seed, one hyper-parameter set. No tuning sweep was run.

## Next runs, in order of expected value

1. **More data.** The curve is still climbing. ~5M positions (≈24 h at this rate) before any
   architectural change is worth making.
2. **Bigger net.** 32 hidden units on 768 features is heavily capacity-limited; 256 units is the
   first step up and costs little training time on this box.
3. **Stronger opponents.** Self-play between clones teaches the net what the engine already knows.
   Mixing in games against a stronger opponent is what actually moves the frontier.
