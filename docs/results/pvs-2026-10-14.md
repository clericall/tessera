# PVS experiment — implemented, measured, rejected

**Date:** 2026-10-14 · **Engine:** `engine/bb.ter` (bitboards, HCE, null-move + LMR + killers/history)

## What was tried

Principal variation search inside `negamax`: the first legal move at a node gets the full window,
later moves are probed with a null window and only re-searched with the full window if the probe
beats alpha.

## Result: not a win, and one variant was outright wrong

Measured at depth 9, one thread, tier C:

| variant | opening pos | endgame pos |
|---|---|---|
| baseline (full window every move) | -13 cp / **1,020,764** nodes | +55 cp / 131,543 nodes |
| probe around `alpha0` (node-entry alpha) | +324 cp / 649,109 nodes | +776 cp / 101,167 nodes |
| probe around current `alpha` | -15 cp / 1,204,029 nodes | +31 cp / 188,695 nodes |

The middle column is a **correctness** finding, not a speed one: probing around `alpha0` (the alpha
the node was *entered* with, rather than the alpha it has reached) returns absurd scores. The probe
window can sit far below the current alpha, the child fails low with a bound, and the bound then
propagates through the fail-soft returns instead of triggering a clean re-search. Two other A/B
builds were made specifically to chase this down, and the `alpha`-based probe is the only correct
one.

With the correct probe, PVS is **slower**: 1.20M nodes vs 1.02M. The usual reason is TT pollution —
null-window probes store upper/lower bound entries that are then re-searched at the same depth, and
this engine's TT keeps only a key/depth/score/flag record with no bound-type separation, so those
re-searches are not cheap. The saving from narrower windows does not cover them.

## Decision

PVS was removed from `engine/bb.ter` (the code is left out, with a comment pointing here). It is not
free complexity when it makes the engine slower.

## What would change the answer

1. **TT bound types** — storing whether an entry came from a null window lets later searches fail
   hard on it instead of re-searching. This is the textbook precondition for PVS to pay off.
2. **Move ordering quality** — PVS only saves nodes when most late moves fail the null window
   immediately. The current ordering (captures + killers + history) helps but is not yet good enough
   to make probes cheap.
3. Then re-measure the same table; the target is clearly fewer nodes at the same depth.
